# BUG-002: Coronal atlas labels rendered as continuous values

## Confirmed behavior

The coronal annotation slice previously passed raw atlas region IDs to a
continuous `turbo` colormap as point scalars. Atlas IDs are categorical, and
their numeric magnitudes have no color meaning. Background ID 0 therefore
received a visible color, large IDs compressed smaller IDs into a narrow part
of the colormap, and interpolation could create colors not present in the
annotation.

The annotation axis conversion is unchanged by this fix.

## Root cause

The renderer treated categorical region IDs as interpolated continuous scalar
values. The ontology loader also discarded Allen `color_hex_triplet` values.

## Fix

- Preserve normalized Allen ontology colors.
- Convert each unique region ID to a stable RGBA value before rendering.
- Make background ID 0 fully transparent.
- Use the existing deterministic color function for unknown IDs.
- Store colors as cell data on a grid whose cell centers retain the original
  annotation pixel coordinates.

## Validation

Automated tests cover ontology color parsing, transparent background, stable
known and fallback colors, independence from ID magnitude, array ordering, and
cell-grid geometry. The full unit-test suite, privacy scan, and packaged
self-test must pass before merge.

Manual validation uses coronal indices at both volume limits and a populated
middle slice. The middle slice must show transparent background, sharp region
boundaries, stable discrete colors, and unchanged world Z placement.
